# Salesforce-style API Documentation

This repository exposes a Salesforce-style API under `/salesforce`.

## Base URL

- `http://localhost:3000/salesforce`

## Users first

This API is user-centric. Users are the primary identities, and both groups and accounts are assigned to users.

### Key user endpoints

- `GET /salesforce/users` - list users with `Location`, `Country`, `Status`, `GroupIds`, and `AccountIds`
- `GET /salesforce/users/:userId` - retrieve one user
- `POST /salesforce/users` - create a user
- `POST /salesforce/users/:userId/groups` - assign groups to a user
- `POST /salesforce/users/:userId/accounts` - assign accounts to a user by ownership
- `PATCH /salesforce/users/:userId` - update user profile fields
- `DELETE /salesforce/users/:userId` - delete a user

## Pagination

Endpoints that return collections use header-based pagination:

- `page` - page number, starting at `1`
- `max` - number of records per page, default `20`, maximum `30`

Example headers:

```http
page: 1
max: 20
```

## Endpoints

### GET /salesforce/users

Returns a paginated list of users.

Response shape:

```json
{
  "page": 1,
  "max": 20,
  "total": 10,
  "count": 10,
  "users": [
    {
      "Id": "<uuid>",
      "Name": "Alice Johnson",
      "Email": "alice.johnson@example.com",
      "Location": "New York",
      "Country": "US",
      "Status": "Active",
      "GroupIds": ["<group-uuid>"],
      "AccountIds": ["<account-uuid>"]
    }
  ]
}
```

### GET /salesforce/users/:userId

Returns a single user record including location, country, and account assignments.

Response shape:

```json
{
  "Id": "<uuid>",
  "Name": "Alice Johnson",
  "Email": "alice.johnson@example.com",
  "Location": "New York",
  "Country": "US",
  "Status": "Active",
  "GroupIds": ["<group-uuid>"],
  "AccountIds": ["<account-uuid>"]
}
```

### POST /salesforce/users

Creates a new Salesforce user.

Request body example:

```json
{
  "record": {
    "Name": "New User",
    "Email": "new.user@example.com",
    "Location": "Austin",
    "Country": "US",
    "Status": "Active"
  },
  "GroupIds": ["<group-uuid>"],
  "AccountIds": ["<account-uuid>"]
}
```

The endpoint also accepts `User` or `user` payload wrappers instead of `record`.

### POST /salesforce/users/:userId/groups

Assigns groups to a Salesforce user.

Request body example:

```json
{
  "GroupIds": ["<group-uuid>"]
}
```

The endpoint also accepts `groupIds` in lowercase.

### POST /salesforce/users/:userId/accounts

Assigns accounts to a Salesforce user by ownership.

Request body example:

```json
{
  "AccountIds": ["<account-uuid>"]
}
```

The endpoint also accepts `accountIds` in lowercase.

### PATCH /salesforce/users/:userId

Updates one or more user profile fields.

Request body example:

```json
{
  "Name": "New User",
  "Email": "new.user@example.com",
  "Location": "Austin",
  "Country": "US",
  "Status": "Inactive"
}
```

### DELETE /salesforce/users/:userId

Deletes a user and sets owned account `OwnerId` values to `Unknown`.

## Accounts

### GET /salesforce/accounts

Returns a paginated list of accounts.

Response shape:

```json
{
  "page": 1,
  "max": 20,
  "total": 10,
  "count": 10,
  "accounts": [
    {
      "Id": "<uuid>",
      "Name": "Acme Corp",
      "Industry": "Manufacturing",
      "Type": "Customer",
      "OwnerId": "<user-uuid>",
      "BillingCity": "New York",
      "BillingCountry": "US",
      "AnnualRevenue": 12000000,
      "Status": "Active",
      "GroupIds": ["<group-uuid>", "<group-uuid>"]
    }
  ]
}
```

### POST /salesforce/accounts/:accountId/enable

Enables an account by setting `Status` to `Active`.

### POST /salesforce/accounts/:accountId/disable

Disables an account by setting `Status` to `Inactive`.

## Groups

### GET /salesforce/groups

Returns all groups.

Response shape:

```json
{
  "total": 20,
  "groups": [
    {
      "Id": "<uuid>",
      "Name": "Basic Permissions",
      "Description": "Read access for assigned accounts.",
      "Permissions": ["Read assigned accounts"]
    }
  ]
}
```

## Workday → Salesforce Mapping

Use Workday employee attributes to form Salesforce user payloads. The primary correlation attribute between Workday (Identity) and Salesforce (user) is `email`.

### Suggested mapping
- Salesforce `Id` => Autogenerated!
- Workday `email` → Salesforce `Email` and user correlation key
- Workday `displayName` → Salesforce `Name`
- Workday `location` → Salesforce `Location`
- Workday `country` → Salesforce `Country`
- Workday `status` → Salesforce `Status` (Active or Inactive)
